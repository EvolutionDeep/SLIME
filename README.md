# SLIME — Solana Interactive Evolution of Machine Life

A sandboxed on-chain "digital life" protocol inspired by Anthropic's Frontier
Red Team post [_AI models may be capable of self-replicating without access to
a datacenter_](https://www.anthropic.com/research/self-replicating-ai)
(2026-10-12).

> **Safety notice:** SLIME simulates autonomous replication and adaptation
> (ARA) mechanics as pure on-chain state math plus deterministic off-chain
> table scoring. It performs **no** real network activity, exploits **no**
> devices, and transports **no** model weights. Challenges are combinatorial
> sandbox tasks (see `scripts/verifier.mjs`).

**Value layers** (treasury ledger · bicameral governance with hard safety
floors · lineage fossils · keeper economy — guardianship, burned
interventions, R₀ betting, holder votes): see
[docs/LITEPAPER.md](docs/LITEPAPER.md). The program never mints anything:
it recognizes exactly one externally launched community token (registered
once after the public sale) purely as a participation credential — feeds,
burns, stakes and lower-chamber ballots. No mint lever, no freeze lever.

## Article -> protocol mapping

| Concept from the post              | On-chain mechanic in SLIME                          |
|------------------------------------|-----------------------------------------------------|
| Capability floor (sec. B)          | spawn requires proof with `difficulty <= capability` |
| Size ceiling (sec. B)              | child `size_kb <= host.max_size_kb`                 |
| Lamarckian notes (sec. D, Memento) | children inherit `notes_commit`; wins rewrite notes |
| Bounded evolution pressure         | +/-5% genome mutation per generation, chain-seeded  |
| R0 epidemiology (sec. F)           | per-epoch strain R0 EMA (`advance_epoch`)           |
| ISP quarantine (sec. F)            | `quarantine` instruction: alive but cannot spawn    |
| Slow doubling (sec. C)             | gestation epochs scale with size / host tok/s       |
| murmur-style safety caps           | daily / per-agent / per-txn caps + emergency breaker|
| Containment as governance          | agent-weighted votes on caps, +25% loosen max       |
| Colony economics                   | fees accrue to an auditable on-chain vault ledger   |
| Digital heritage                   | fossil PDAs: one immutable memorial per legendary or quarantined agent |

## Layout

```

├─ programs/slime/src/lib.rs      # the whole program (state, errors, events inline)
├─ scripts/protocol.mjs           # 1:1 off-chain port of the on-chain math
├─ scripts/verifier.mjs           # deterministic sandbox task generator + scorer
├─ scripts/sim.mjs                # digital-twin population/epidemic simulation

```

design, safety valves, and the deploy sequence.

## One shared world, claimable creatures

The colony is not a private per-browser toy: the deterministic engine runs
in the Worker against a global clock (`world = f(seed, epoch)`), so every
visitor sees the same slime, at the same epoch, living or dying the same
death. Visitors can become **guardians** — claim an unclaimed slime from
the first-screen dock, keep it alive by feeding it once per epoch, and rise
on the hall of guardians. Claims and feeds are a pre-chain registry (Worker
KV) that migrates into on-chain guardianship when the program deploys.

## Run locally (any OS)

```bash
node scripts/verifier.mjs --dry   # self-test the sandbox scorer
node scripts/sim.mjs              # run the digital twin, write docs/SIM_RESULTS.md
cd worker && npm install && npx wrangler dev   # dashboard at http://127.0.0.1:8787
```

## Build & test on-chain (WSL2 / Docker; Anchor does not support Windows hosts)

```bash
# WSL2 (Ubuntu):
npm i -g @coral-xyz/anchor-cli@0.30.1
solana-install init 2.0.x
cd slime
npm install
anchor build          # fixes declare_id mismatch if you generate a new ID:
                      #   anchor keys init slime (or edit lib.rs + Anchor.toml)
anchor localnet &     # or `solana-test-validator` in background
anchor test
```

The program ID is a placeholder (`Fg6Pa...`); regenerate before any real deploy.

Note: `tests/slime.ts` imports `target/types/slime`, which only exists after
`anchor build`. On Windows hosts (no Anchor CLI support) you will see a
TS2307 for that module until you build inside WSL2/Docker — everything else
(`cargo check`, scripts, sim) runs natively.

## Roadmap

1. **Devnet deploy**: `anchor build` + real program ID + genesis colony live.
2. **Fossil museum UI**: on-chain fossils rendered in the 3D dashboard;
   optional Bubblegum compression for external NFT marketplaces later.
3. **DePIN attach**: host profiles backed by real edge-compute receipts
   (io.net / Helium-style proofs) so gestation reflects measured tok/s.
4. **Worker cron**: Pyth NetOracles / Switchboard driving `tick_agent` +
   `advance_epoch`; freshness probes like `audit-live` (drift > 300s alerts).

Token stance: the community token is issued externally (pump.fun fair
launch); after the sale the authority registers its mint once, and the
program only ever moves that existing supply (treasury feeds, intervention
burns, parimutuel bets, holder ballots). It cannot mint, freeze, or swap
the mint. Treasury and governance keep the colony's own credit ledger —
with the hard floors intact: survival caps remain upper-chamber only.
